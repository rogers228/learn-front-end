# 檔案系統路由

資料夾決定網址，+page.svelte 決定畫面


src/routes/
├── +layout.svelte             <-- 全站共用的 Header / Footer
├── +page.svelte               <-- 首頁 (網址: /)
├── about/
│   └── +page.svelte           <-- 關於我們 (網址: /about)
└── products/
    └── [id]/                  <-- 動態路由，例如 /products/p123
        ├── +page.svelte       <-- 產品頁畫面
        └── +page.server.js    <-- 產品頁後端（向 Supabase/Worker 抓 Big JSON）




# `+`前綴號

`+`前綴號 是代表 SvelteKit 的路由保留關鍵字，固定的名稱不能改變

+page.svelte        頁面的 UI 畫面
+page.js            頁面的資料載入器（執行於 Client + Server）
+page.server.js     頁面的伺服器端資料載入器（只執行於 Server/Edge，適合抓 D1/Supabase/API）
+layout.svelte      該層級與子目錄共用的外框 (Header / Footer / Sidebar)
+layout.server.js   Layout 專用的伺服器資料載入器（例如：全站登入狀態、購物車數量）
+server.js          純 API 端點 (回傳 JSON、檔案串流，類似原生 Worker 的 fetch)
+error.svelte       該層級發生錯誤時顯示的客製化錯誤頁面

src/routes/products/[id]/
├── +page.svelte          <-- 網址 /products/123 的主要頁面 (SvelteKit 關鍵字)
├── +page.server.js       <-- 伺服器端抓 Big JSON (SvelteKit 關鍵字)
├── ProductCard.svelte    <-- 只有這個頁面會用到的 Svelte 元件 (普通檔案，不影響路由)
├── ProductGallery.svelte <-- 只有這個頁面會用到的圖片輪播元件 (普通檔案)
└── utils.js              <-- 專屬工具函式 (普通檔案)


## 1. 基本路由
（資料夾名 = 網址）你建什麼資料夾，網址就是什麼：資料夾結構對應的網址 (URL)說明

src/routes/+page.svelte                   /             網站首頁
src/routes/about/+page.svelte             /about        關於我們
src/routes/contact/us/+page.svelte        /contact/us   嵌套資料夾，對應多層網址


## 2. 動態路由：用中括號 [變數]

資料夾結構                               對應的網址 (URL)        變數抓取方式 (params)

src/routes/products/[id]/+page.svelte    /products/p100        params.id 就會拿到 'p100'


src/routes
/users/[userId]/posts/[postId]/+page.svelte     /users/alex/posts/99     params.userId 為 'alex'  params.postId 為 '99'

## 3. 路由忽略資料夾 使用小括號
src/routes/
├── (shop)/                  <-- 小括號：網址會忽略它！
│   ├── +layout.svelte       <-- 購物網站專用的 Header/Footer
│   ├── +page.svelte         <-- 網址仍然是: / (不是 /shop)
│   └── products/
│       └── +page.svelte     <-- 網址仍然是: /products (不是 /shop/products)
│
└── (admin)/                 <-- 小括號：網址會忽略它！
    ├── +layout.svelte       <-- 後台管理專用的 Sidebar/TopBar
    └── dashboard/
        └── +page.svelte     <-- 網址是: /dashboard (不是 /admin/dashboard)


## 4. 通配符路由（Catch-all）：[...rest]

資料夾

src/routes/docs/[...slug]/+page.svelte
(slug 在 Web 開發中常用來指稱「網址最後面那串文字」  慣例）
它可以是任意名稱，例如`[...path]`


你命名的資料夾名稱造訪網址 (URL)在 Code 裡拿到的 params 內容

src/routes/docs/[...slug]      /docs/guide/installparams           params.slug=guide/install'
src/routes/files/[...path]     /files/2026/08/photo.png            params.path='2026/08/photo.png'
src/routes/category/[...anything]  /category/shoes/nike/air-max    params.anything='shoes/nike/air-max'


匹配網址：
/docs/a         arams.slug 為  'a'
/docs/a/b/c     params.slug 為 'a/b/c'




# 複雜參數的分流原則


資源層級 (網址骨架)： 用資料夾動態路由      [company]/[product] （SSR / SEO 最愛）
視圖/篩選模式： 用Query String     ?mode=report&page=2 （伺服器與前端都能讀，方便分享網址）。
錨點/微小狀態： 用 #hash + Client-side 監聽
臨時/滾動位置： 用 SvelteKit snapshot   滾動到第 500px、Tab 頁籤
