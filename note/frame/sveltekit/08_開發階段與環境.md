# 環境大致有分為

1. Local Dev（本地開發）：你在電腦上跑 npm run dev 或 01_dev.bat。

2. Preview（預覽/測試環境）： 當你 Push 程式碼到非 main 分支 或是開 Pull Request 時，Cloudflare Pages 會自動為該次提交產生獨立的測試網址（如 https://<hash>.ispc-core2.pages.dev）。

3. Production（正式環境）:    你 Push 程式碼到 main 分支時，Cloudflare 會發布到正式網址


# Cloudflare 識別環境

Cloudflare 的底層機制是基於 Git 分支

Production 觸發：系統綁定你的 main 分支

Preview 觸發: 非main


# 如何識別環境
比對 Domain 網址（簡單直覺）
當你有綁定自訂網域（如 [https://example.com](https://example.com)）時，這個方法最簡單，因為只有正式環境會綁定主網域，所有測試環境都是 Cloudflare 隨機產生的 .pages.dev 網址：

const isProduction = url.hostname === 'ispc-core2.pages.dev';


# 個人開發 git 方式，取得  Cloudflare 測試網址

使用 Cloudflare 開分支不再是為了「跟別人協作」，而是為了取得「強大的免費測試環境（Staging Environment）」！


```
[ main 分支 ]  --------------------------> [ 正式站：your-domain.com ]
      \                                        ^
       \ (開新分支)                             | (合併 Merge)
        v                                      |
[ feature/xxx 分支 ] -> Cloudflare Pages 自動生成預覽站 
                       (https://xxx.ispc-core2.pages.dev)
```


main 分支：永遠保持為線上正式運作的程式碼（只有測試過沒問題的才能放這裡）

feature/xxx 分支：每個新功能或大修改獨立開一個分支。這個分支上傳後，Cloudflare 會自動生成一個獨立的測試網址給你看，完全不會影響線上正在運作的正式網站！



# 實際測試
## 步驟 1：建立新功能分支（Feature Branch）

打開 GitHub Desktop，點擊頂部的 Current Branch。
點擊 New Branch，輸入功能名稱（例如 feature/robots）。點擊 Create Branch。

## 步驟 2：發布測試分支

取得 Cloudflare 預覽網址在編輯器寫完 Code 存檔後，回到 GitHub Desktop。左側勾選變更檔案，輸入 Commit 訊息，點擊 Commit to feature/robots）。點擊。點擊右上角藍色的 Publish branch（或 Push origin）。完成！

Cloudflare 收到後就會自動產生專屬測試網址

它是在 進入worker > Deployments 頁籤 > Version History 列表 > version no 是超連結，點下去就是分支網址了


## 步驟 3：測試完成合併回 main 發布正式站

1. 在 GitHub Desktop 頂部將 Current Branch 切換回 main。
2. 點擊選單列的 Branch > Merge into current branch...。選擇你的 feature/robots 分支並點擊 Merge。
3. 按右上角的 Push origin，正式站馬上自動更新！
