媒體查詢策略


在 SvelteKit 中，最佳策略：CSS 負責「顯示/隱藏」，JS 負責「互動狀態」

過往大家常犯的錯誤是：用 JS 狀態（如 $state(isOpen)）去決定「要不要渲染（{#if}）選單 DOM」。這會直接導致 SSR 出錯。


## 改進後的邏輯是：

DOM 永遠留在 HTML 裡面（讓 SSR 能直接印出來）。

CSS 媒體查詢（Tailwind / Bulma / CSS）負責控制防禦層：桌機版隱藏漢堡按鈕，手機版隱藏預設展開的選單。

Svelte UI 狀態只負責控制「使用者主動點擊後的 Toggle 動作」。

## 實作範例：以 Tailwind CSS + Svelte 5 為例

``` html
<!-- Navbar.svelte -->
<script lang="ts">
  // 1. JS 只管理「使用者是否主動打開選單」的狀態，預設為 false
  // 不可以使用 {#if} 來改變 DOM

  let isMenuOpen = $state(false);

  function toggleMenu() {
    isMenuOpen = !isMenuOpen;
  }

</script>

<header class="flex items-center justify-between p-4 bg-slate-900 text-white">
  <div class="text-xl font-bold">Logo</div>

  <!-- 
    2. 漢堡按鈕：
    - 使用 CSS 媒體查詢 (md:hidden) 強制在桌機版隱藏。
    - 伺服器渲染時不論螢幕多寬，這個 Class 都能確保桌機版絕對不會出現按鈕。
  -->
  <button 
    onclick={toggleMenu} 
    class="md:hidden p-2 text-2xl"
    aria-label="Toggle Navigation"
  >
    🍔
  </button>

  <!-- 
    3. 導覽選單（關鍵防禦）：
    - 絕不使用 {#if isMenuOpen} 圍繞整個選單！
    - 桌機版 (md:flex)：強制顯示為水平選單（忽視 isMenuOpen 狀態）。
    - 手機版 (flex)：根據 isMenuOpen 決定是 hidden 還是 flex。
  -->
  <nav class={`
    absolute top-16 left-0 w-full flex-col bg-slate-800 p-4
    md:static md:w-auto md:flex-row md:bg-transparent md:p-0 md:flex
    ${isMenuOpen ? 'flex' : 'hidden'}
  `}>
    <a href="/" class="py-2 md:py-0 md:px-4">首頁</a>
    <a href="/about" class="py-2 md:py-0 md:px-4">關於我們</a>
    <a href="/contact" class="py-2 md:py-0 md:px-4">聯絡我們</a>
  </nav>
</header>

```
